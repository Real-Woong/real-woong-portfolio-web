# BubbleBreak

# **📌 BubbleBreak**

### **오프라인 첫 만남을 위한 관심사 기반 아이스브레이킹**

동아리, 스터디, 네트워킹 모임 등 처음 만나는 사람들끼리

**공통 관심사를 자연스럽게 발견하고 오프라인 대화를 시작하도록 돕는**

비로그인 · 쿠키 세션 기반 웹 서비스입니다.

방장이 방을 만들면 참가자는 방 코드만으로 로그인 없이 입장하고,

각자의 관심사를 공개 범위가 다른 3단계 민감도로 등록한 뒤,

서로의 관심사 버블을 눌러(pop) 흥미를 표현합니다.

랜덤 채팅처럼 온라인에서 낯선 사람과 매칭하는 서비스가 아니라,

**이미 같은 공간에 있는 사람들이 대화를 시작할 계기를 만들어주는 도구**입니다.

---

# **🏗 현재 구현 상태**

### **소규모 실사용 데모 운영 중**

- React + Vite 프론트엔드, Cloudflare Workers + D1 풀스택 아키텍처
- 방 생성 → 참여 → 관심사 등록 → 준비완료 → 버블 필드 → 종료까지 전체 room lifecycle 구현
- 방 코드 기반 입장과 `HttpOnly · Secure · SameSite=Lax` 쿠키 세션
- 관심사 민감도 3단계(공개 / 반공개-블러 / 비공개-잠금) 등록 및 노출 제어
- 버블 pop 인터랙션과 pop 기반 실시간 알림
- 실제 pop 이벤트를 근거로 한 방 종료 요약 화면
- Cloudflare Worker 단일 배포(정적 자산 + API)와 Cron Trigger 기반 정리 작업

프론트엔드(GitHub Pages 계열)와 백엔드(Worker)가 분리 배포되는 구조라는 점을 실제 운영 중 직접 겪었고,

지금은 Worker 주소(`bubblebreak-demo.jinung344.workers.dev`)를 정식 서비스 주소로 정리해 운영하고 있습니다.

# **💡 핵심 기능**

### **1️⃣ 방 코드 기반 비로그인 참여**

회원가입 없이 방장이 만든 방 코드만으로 누구나 즉시 입장할 수 있습니다.

- 입장 시 `bb_session` 쿠키 발급, 서버가 참가자 세션을 식별
- 방장의 시작/종료, 참가자의 준비완료 상태를 room 단위로 동기화
- 방 나가기, 세션 만료 시 자동으로 입장 화면으로 복귀

인증 시스템 없이도 room 참여자 신원과 권한을 안전하게 구분하는 데 초점을 맞췄습니다.

---

### **2️⃣ 3단계 민감도 관심사 버블**

참가자는 자신의 관심사를 공개 수위가 다른 세 단계로 등록합니다.

- **deep1 (가볍게)** — 방 전체에 항상 텍스트가 공개
- **deep2 (조금더)** — 항상 블러 처리되어 있고, 본인 것이거나 이미 pop한 버블만 블러가 풀림
- **deep3 (비밀취향)** — 잠금 상태로만 노출되고, 대상자가 열람을 승인해야 텍스트가 공개

같은 관심사라도 상대에게 어디까지 보여줄지 스스로 정할 수 있게 해,

처음 만난 사이에서도 부담 없이 취향을 드러낼 수 있도록 설계했습니다.

---

### **3️⃣ 버블 Pop과 실시간 알림**

버블 필드에서 다른 참가자의 관심사 버블을 누르면(pop) "나도 이 관심사에 흥미가 있다"는 신호가 상대에게 전달됩니다.

- pop 대상자에게는 "OO님이 당신의 '흥미'를 확인했어요" 형태의 토스트 알림 발생
- deep3(비공개) 관심사는 pop 대신 열람 요청을 보내고, 요청이 오면 대상자에게 즉시 알림
- 요청을 수락해야만 실제 텍스트가 공개되는 승인 구조
- 동일 조합(같은 대상·같은 관심사) pop은 서버에서 멱등 처리되어 연타해도 이벤트가 중복 적재되지 않음

원래는 알림 없이 화면을 직접 열어야만 확인 가능했던 부분을, 이벤트 발생 즉시 알 수 있도록 개선했습니다.

---

### **4️⃣ 실제 Pop 기반 방 종료 요약**

방이 종료되면 "누가 누구와 어떤 관심사로 연결됐는지"를 정리해 보여줍니다.

텍스트 유사도 매칭(예: "야구" vs "야구직관")은 표현 차이 문제를 그대로 안고 있어 시도하지 않았고,

대신 **서버에 이미 기록된 실제 pop/승인 이벤트를 그대로 근거로 사용**하는 방식을 택했습니다.

- 참가자 쌍(A, B) 단위로 이벤트를 모아 양방향 pop이 확인되면 "상호 확인(mutual)"으로 강조 표시
- 한쪽만 pop한 경우는 단방향 리스트로 약하게 표시
- deep3(비공개) 관심사는 그 이벤트의 당사자에게만 텍스트가 노출되고, 나머지 참가자에게는 가려짐
- 이 요약을 근거로 아이스브레이커 대화 제안 문장 생성

각자 다른 단어로 같은 취향을 표현해도, 실제 행동(누가 누구의 버블을 눌렀는지) 자체가 매칭 근거가 되도록 설계했습니다.

---

### **5️⃣ 소규모 실사용을 고려한 폴링 구조**

Durable Objects 없이도 참가자 간 상태를 충분히 빠르게 동기화하도록,

Lobby/버블 필드 화면에서 짧은 주기 폴링과 하트비트를 기본으로 켜서 운영합니다.

- 데모 규모(소수 사용자)에 맞춰 폴링 주기를 조정해 서버 부하와 체감 반응 속도의 균형을 맞춤
- 세션 stale 판정 기준을 폴링/하트비트 동작 방식에 맞춰 재조정해, 가만히 있어도 세션이 조용히 끊기지 않도록 수정
- 완전한 push 방식(WebSocket/Durable Objects)은 다음 단계 개선 과제로 분리

# **🧩 해결한 기술적 문제**

### **모든 요청마다 실행되던 방 정리 로직**

기존에는 정적 자산 요청을 포함한 모든 API 요청마다 만료된 방을 정리하는 쿼리가 함께 실행되어,

방 개수가 늘어날수록 무관한 요청까지 느려지는 구조였습니다.

정리 로직을 요청 경로에서 완전히 분리하고 Cloudflare **Cron Trigger**(`scheduled` 핸들러)로 옮겨,

일정 주기로만 독립 실행되도록 재구성했습니다.

### **Pages와 Worker가 분리 배포되는 구조를 모른 채 운영**

`git push`로 프론트엔드 저장소는 자동 배포됐지만, 실제 API를 처리하는 Cloudflare Worker는

별도의 `wrangler deploy` 없이는 절대 갱신되지 않는다는 점을 인지하지 못해 프로덕션이 완전히 멈춘 적이 있습니다.

원인이 되는 유령 Pages 배포를 확인하고, Worker 주소를 정식 서비스 주소로 전환한 뒤

배포 스크립트(`wrangler deploy`)를 통해 프론트/백엔드를 함께 배포하는 흐름으로 정리했습니다.

### **SameSite 쿠키가 로컬 개발에서만 조용히 실패하던 문제**

프론트는 `localhost`, API는 `127.0.0.1`로 각각 다른 호스트를 바라보고 있었는데,

브라우저의 SameSite 쿠키 규칙상 이 둘은 서로 다른 사이트로 취급되어 인증이 계속 실패했습니다.

두 호스트를 `localhost`로 통일해 해결했고, 이 과정에서 SameSite 동작 방식을 정확히 이해하게 됐습니다.

### **불필요한 재요청을 유발한 의존성 배열 실수**

세션 초기화 함수를 다른 컴포넌트의 `useCallback` 의존성 배열에 추가하는 과정에서,

함수가 매 렌더마다 새로 생성되며 렌더 → 재요청 → 재렌더가 반복되는 무한 루프가 발생했습니다.

네트워크 요청 로그에서 짧은 시간에 수백 건의 중복 요청을 확인한 뒤,

원인이 된 함수를 `useCallback`으로 메모이즈해 해결했습니다.

# **🚧 개발 상태**

### **구현 완료**

- 방 생성/참여/준비완료/시작/종료 room lifecycle
- 방 코드 기반 비로그인 쿠키 세션 (`HttpOnly · Secure · SameSite=Lax`)
- 민감도 3단계 관심사 등록 UI
- 버블 필드 pop 인터랙션과 deep2 블러/deep3 잠금 노출 제어
- pop 대상자 알림, deep3 열람 요청 알림
- 실제 pop 이벤트 기반 방 종료 요약 및 상호 매칭 표시
- deep3 프라이버시 마스킹(당사자 외 비공개)
- pop 이벤트 서버 멱등 처리
- 401 세션 만료 자동 감지 및 입장 화면 복귀
- Cloudflare Cron Trigger 기반 만료 방 정리
- 화면별 뒤로가기 내비게이션, 레이아웃 폭 정합성 수정
- Cloudflare Worker 단일 배포(정적 자산 + API) 및 실사용 배포 전환

### **향후 계획**

- Durable Objects 기반 실시간 push로 폴링 대체
- 방 규모 확장 시 폴링/부하 구조 재검토
- 관심사 입력 UX 및 추천 문장 생성 고도화
- 종료 요약 화면 시각적 개선(연결 그래프 등)

# **🧠 프로젝트에서 중요하게 생각한 점**

BubbleBreak는 사람과 사람이 실제로 마주 앉은 자리에서

**"할 말이 없어서 흥미를 잃고 자리를 뜨는 순간"을 줄이기 위한 프로젝트**입니다.

개발 과정에서 다음 원칙을 특히 중요하게 다뤘습니다.

- 관심사 표현을 고정 태그로 강제하지 않고, 실제 pop 행동 자체를 매칭 근거로 삼아 표현의 자유도를 지킴
- 온라인 랜덤 매칭이 아니라 이미 같은 공간에 있는 사람들의 오프라인 대화를 돕는 것에 집중
- 무거운 인증 없이도 쿠키 세션만으로 안전하게 참가자를 구분
- 공개 범위를 강제하지 않고 참가자가 직접 3단계로 조절하게 해 부담을 낮춤
- 요청 경로에서 무거운 로직을 분리하고 배포 구조를 정확히 이해해 실사용 가능한 서비스로 운영
