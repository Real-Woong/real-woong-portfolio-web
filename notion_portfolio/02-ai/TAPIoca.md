# **🧋 TAPIoca**

### **Toss API-based Investment Agent**

TAPIoca는 토스증권 Open API를 활용해 사용자의 포트폴리오와 시장 데이터를 분석하고, 정해진 투자 원칙에 따라 **가상 매매(PAPER Trading)** 를 수행하는 개인 투자 에이전트 실험 프로젝트입니다.

프로젝트 이름 **TAPIoca**는 **Toss API**를 줄인 `TAPI`와 친숙한 단어인 `Tapioca`를 결합해 만들었습니다.

현재는 실제 주문을 실행하지 않으며, 다음 데이터를 기반으로 투자 전략과 자동화 구조를 검증하고 있습니다.

- 토스증권 계좌 및 시장가격 데이터
- FRED 미국 거시경제 지표
- Federal Reserve 공식 발표 및 경제 뉴스
- MACD 가격 추세 보조 신호
- PAPER Trading 누적 거래 결과

현재 TAPIoca의 주요 테스트 인터페이스는 **Telegram**입니다.

가상 매매 결과와 포트폴리오 상태, 시장 판단, 손익을 매일 Telegram 메시지로 받아보며 실제 사용 환경에서 보고서가 이해하기 쉽고 유용한지 검증하고 있습니다.

# **💡 핵심 기능**

### **1️⃣ Toss API 포트폴리오 조회**

토스증권 Open API를 통해 사용자의 계좌와 보유 종목을 조회합니다.

현재 확인할 수 있는 정보는 다음과 같습니다.

- 국내·미국 주식 보유 현황
- 종목별 보유 수량
- 종목별 평가금액
- 종목별 수익률
- 원화·달러 자산 구성
- 종목별 포트폴리오 비중
- 포트폴리오 집중도 지수
- 조회 가능한 종합매매 계좌

Toss API 연동은 현재 **조회 전용**으로 사용합니다.

실제 매수·매도 주문 API는 구현하지 않았으며, PAPER Trading 장부와 사용자의 실제 증권 계좌는 서로 분리되어 있습니다.

---

### **2️⃣ 포트폴리오 분석**

수집한 계좌 데이터를 기반으로 사용자의 포트폴리오 구조를 분석합니다.

주요 분석 항목은 다음과 같습니다.

- 종목별 투자 비중
- 원화·달러 자산 구분
- 특정 종목 집중도
- 포트폴리오 집중도 지수(HHI)
- 과도한 단일 종목 비중 경고
- 통화별 평가금액
- 자산 분산 상태

단일 종목 비중이 지나치게 높으면 주의 메시지를 표시하도록 설계했습니다.

이 기능은 실제 주문을 생성하지 않으며, 현재 포트폴리오의 구조를 이해하기 위한 조회·분석 기능으로 사용합니다.

---

### **3️⃣ FRED 거시경제 분석**

FRED에서 미국의 주요 경제지표를 수집하고 현재 시장 환경을 세 가지 상태로 분류합니다.

- **RISK ON**
- **NEUTRAL**
- **RISK OFF**

판단에 활용하는 주요 지표는 다음과 같습니다.

- 미국 기준금리
- 근원 PCE
- 실업률
- Sahm Rule 지표
- 미국 10년물·2년물 금리 차이

FRED 분석 결과에 따라 VTI, SCHD, IWM과 현금의 실험용 목표 비중을 계산합니다.

거시경제 신호는 즉시 매수·매도 명령으로 사용하지 않으며, **신규 투자 비중을 조절하는 기본 판단 기준**으로 사용합니다.

현재는 FRED 결과에 다음 보조 신호를 결합합니다.

**공식 뉴스 감성**

- Federal Reserve 공식 RSS
- GDELT 경제뉴스
- 선택한 공개 Bluesky 계정
- Substack 및 개인 블로그 RSS
- 로컬 감성 분석기
- 선택적으로 Ollama 로컬 모델 사용 가능

**MACD 보조 신호**

- 15분 단위 ETF 가격 저장
- 12·26·9 MACD 계산
- 최소 34개 가격 표본 필요
- 여러 ETF의 방향 일치도를 신뢰도로 반영

통합 시장 점수는 다음 구조로 계산합니다.

```
기본 점수 = FRED 점수 + 뉴스 감성 점수 × 감성 신뢰도 × 감성 가중치

최종 점수 = 기본 점수 + MACD 점수 × MACD 신뢰도 × MACD 가중치
```

뉴스 감성과 MACD는 단독 매매 신호가 아니라 FRED 기반 시장 상태를 보조하는 용도로 제한합니다.

### **4️⃣ PAPER Trading 시스템**

실제 자금을 사용하지 않고 가상의 투자 장부를 통해 ETF 매매 전략을 검증합니다.

현재 PAPER Trading은 다음 원칙으로 작동합니다.

- 초기 실험 원금 100,000원
- 미국 ETF 중심 투자
- 실제 계좌와 PAPER 장부 분리
- 1회 투자금액 제한
- 최소 주문금액 적용
- 하루 최대 매수금액 제한
- 일일·누적 최대 손실 제한
- 손실 한도 도달 시 신규 매수 중단
- 정해진 위험 한도 안에서만 신규 진입
- 이전 실행의 장부를 이어서 사용
- 임시 파일과 rename을 이용한 안전한 장부 저장
- 중복 실행 방지를 위한 잠금 파일 사용

현재 기본 주문 정책은 다음과 같습니다.

```
초기 원금: 100,000원
1회 최대 매수: $5
최소 주문금액: $1
하루 최대 매수: $10
청산 후 재진입 대기시간: 24시간
```

`$1` 미만의 작은 목표 비중 차이는 주문하지 않습니다.

이를 통해 `$0.02`, `$0.04`처럼 의미가 작은 주문이 15분마다 반복되는 문제를 방지했습니다.

현재 실행기는 **LIVE Trading을 허용하지 않으며 실제 주문 API를 호출하지 않습니다.**

### **5️⃣ 리스크 관리 및 청산 정책**

에이전트가 PAPER 장부에서 직접 생성한 포지션만 자동 청산 대상으로 관리합니다.

현재 적용된 청산 기준은 다음과 같습니다.

**손절 청산**

- 평균 진입 가격보다 설정 비율 이상 하락하면 손실 제한
- 기본 손절 기준은 3%

**추적 수익 청산**

- 일정 수익률에 도달한 뒤 고점 대비 하락하면 수익 실현
- 기본 활성화 수익률은 2.5%
- 기본 고점 대비 하락 기준은 1.5%

**최대 보유기간 청산**

- 설정된 기간보다 오래 보유한 포지션 정리
- 기본 최대 보유기간은 15일

**손실 한도 안전장치**

- 일일 손실 한도 도달 시 신규 매수 중단
- 누적 손실 한도 도달 시 신규 매수 중단
- 신규 매수가 중단되어도 기존 포지션의 손절·수익실현 판단은 계속 수행

**재진입 대기시간**

- 청산한 종목을 즉시 다시 매수하지 않음
- 기본 24시간의 재진입 대기시간 적용
- 대기시간이 끝나면 목표 비중 계산에 다시 포함

이전에는 한 번 청산된 종목이 영구적으로 자동매수 대상에서 제외되는 문제가 있었습니다.

현재는 영구 차단 대신 24시간의 재진입 대기시간을 적용하도록 개선했습니다.

에이전트 실행 이전부터 사용자가 실제 계좌에 보유하고 있던 종목은 자동 매도 대상에서 제외됩니다.

### **6️⃣ Telegram 테스트 및 일일 보고서**

현재 TAPIoca에서 가장 집중적으로 테스트하는 기능입니다.

뉴욕 정규장 종료 이후 PAPER Trading 결과를 정리해 **Telegram 메시지로 전달하는 구조**를 구현했습니다.

Telegram 보고서에서는 다음 정보를 확인할 수 있습니다.

- 뉴욕 기준 거래일
- 초기 원금
- 현재 총자산
- 보유 현금
- ETF 평가금액
- 누적 손익
- 실현손익
- 미실현손익
- 누적 거래 횟수
- 통합 시장 상태
- FRED 거시경제 점수
- 무료 뉴스 감성 점수와 신뢰도
- MACD 점수와 준비 상태
- ETF별 목표 비중
- 보유 ETF 현황
- 당일 가상 매매 내역
- 신규 매수 안전 중단 여부
- PAPER 모드 안내

같은 뉴욕 거래일의 보고서가 중복 전송되지 않도록 마지막 전송 거래일과 전송 시각을 별도 상태 파일에 저장합니다.

현재는 Telegram을 통해 **투자 결과를 매일 확인하는 실제 사용 흐름**을 테스트하고 있습니다.

향후에는 단순 결과 전달을 넘어 사용자가 Telegram에서 질문하고 분석 결과를 받아보는 대화형 투자 에이전트 형태로 확장할 계획입니다.

### **7️⃣ 미국 시장 시간 기반 자동 실행**

PAPER Trading은 뉴욕 현지시간을 기준으로 미국 주식 정규장에서만 실행되도록 설계했습니다.

- 뉴욕 기준 평일 09:30~16:00 실행
- 미국 서머타임 자동 반영
- 장외 시간에는 시장가격 조회와 신규 매매 중단
- 서버 부팅 이후 자동 실행
- 15분 간격 PAPER Trading 실행
- 뉴욕 정규장 종료 후 Telegram 일일 보고서 전송
- systemd Service와 Timer를 이용한 자동화

Oracle 서버의 시간대와 관계없이 `America/New_York` 시간대를 기준으로 시장 운영시간과 거래일을 계산합니다.

현재 자동 실행 구성은 다음과 같습니다.

```
toss-ai-paper.timer
→ 미국 정규장에서 PAPER Trading 주기 실행

toss-ai-report.timer
→ 뉴욕 정규장 종료 후 Telegram 일일 보고서 전송
```

이를 통해 서버의 로컬 시간대와 무관하게 실제 미국 시장 운영시간에 맞춰 동작할 수 있습니다.

# **🧠 프로젝트에서 중요하게 생각한 점**

TAPIoca는 단순히 주식을 자동으로 사고파는 프로그램이 아닙니다.

> **“AI 투자 에이전트에게 실제 자산을 맡기기 전에 무엇을 검증해야 하는가?”**
> 

이 질문에 답하기 위한 실험 프로젝트입니다.

특히 다음 원칙을 중심으로 설계했습니다.

- 실제 주문보다 조회와 분석부터 검증
- 투자 판단과 실행 결과를 사람이 확인할 수 있도록 기록
- 실제 보유 자산과 에이전트 포지션 분리
- 투자금과 최대 손실을 코드 수준에서 제한
- 거시경제 신호 하나만으로 즉시 매매하지 않도록 설계
- 뉴스 감성과 MACD는 보조 신호로만 제한
- API 또는 시장 데이터 확인 실패 시 신규 매수 중단
- 의미가 작은 소액 주문 반복 방지
- 청산 직후 동일 종목 재진입 방지
- 모든 전략을 PAPER Trading에서 먼저 검증
- Telegram을 통해 결과를 지속적으로 확인
- 자동 테스트로 안전장치의 실제 동작 검증
- 충분한 데이터가 쌓인 이후에만 다음 자동화 단계 검토

# **🔒 안전장치**

현재 TAPIoca는 실제 주문을 실행하지 않는 **PAPER Trading 전용 프로젝트**입니다.

- LIVE Trading 비활성화
- 실제 주문 API 미사용
- 기존 보유 종목 자동 매도 금지
- 실제 계좌와 PAPER 장부 분리
- 투자 원금 100,000원 제한
- 1회 최대 매수금액 제한
- 하루 최대 매수금액 제한
- 최소 주문금액 `$1`
- 일일·누적 손실 한도 적용
- 손실 한도 도달 시 신규 매수 중단
- 시장 데이터 확인 실패 시 신규 매수 중단
- 청산 후 24시간 재진입 대기
- 미국 정규장 밖에서는 기본 실행 중단
- 중복 프로세스 실행 방지
- 장부 안전 저장
- Telegram 보고서에 PAPER 모드 표시
- Telegram 보고서에 안전 중단 상태 표시
- 전체 자동 테스트 57개 통과

투자 전략의 결과는 수익을 보장하지 않습니다.

현재 설정은 전략 검증을 위한 초기 실험값이며, 충분한 PAPER Trading 데이터와 백테스트 결과가 쌓이기 전에는 실제 주문 기능을 활성화하지 않습니다.
